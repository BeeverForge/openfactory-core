**Every refusal of an action says why in a word a program can read.** A refused action answers `data.reason` beside its `code`: the code itself where nothing finer applies, and otherwise one of `bad_parameters`, `bad_ref`, `out_of_scope`, `not_the_installations`, `not_admin`, `no_code_yet`, `engine_unreachable`, `raised`, `reported_nothing` or, for a name no action has, `unknown_action` — so a credential scoped away from an area and an actor who is not an admin, both `denied`, are told apart. `/api/actions` lists each action's possible reasons as `refusals`.
