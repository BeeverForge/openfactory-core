**A front end checks itself against a release with one command.** `openfactory conformance-client <address> --manifest <file>` reads a small JSON manifest of the routes, fields and event kinds a client uses, asks the API at that address for each of them, and fails naming whatever the API does not have or answers outside what the release promises: a status its description does not name, a body outside the release's model, a refusal without its sentence, or another release than the suite's. It only reads, takes the credential from the environment variable `--token-env` names, and exits 1 on a finding, so a CI job can run it against a pinned image. Without `--manifest` it checks the default front end, whose manifest is read from the page the release ships, and the core's own tests hold the default front end to the same suite. `docs/reference/the-client-contract-suite.md` is the guide. Streams are checked as routes and event kinds only for now: their frames are checked once the typed event stream is served.
- **The board, a product's attachments and a product's documents describe their 404.** Each answered a project the deployment does not hold with a 404, and the API's description named only 200 and 422 for them, so a client of the description had no 404 to expect. The suite found it on its first run.
