**A preview is never handed a variable a harness route requires, and one already in a project's preview policy is dropped when the registry is read.** `OPENAI_API_KEY`, `AZURE_API_KEY`, `AZURE_RESOURCE_NAME`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `CLOUD_ML_REGION` and `VERTEX_REGION` join the factory's own credentials on the list a preview is refused, on either side of a `svc=NAME=WORKER_NAME` mapping: a preview runs code from a pull request nobody merged, and its policy can now be set from the panel by every credential that is the administrator there — the panel's token, a person invited to neither area, and on an identity provider everyone whose groups map to no area. A service of a preview that read one of these names receives nothing under it now; give it the value under a name of its own.
