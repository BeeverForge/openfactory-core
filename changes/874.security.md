**A Jira project is no longer handed the deployment's GitHub token.** A Jira project that named no `token_env`, on a deployment with no `JIRA_API_TOKEN`, fell through to the deployment's own pair (`OPENFACTORY_TRACKER_TOKEN`, then `OPENFACTORY_BOT_TOKEN`) and sent that GitHub token to the Jira site, which refused it as another account's. A vendor whose credential row names its own variable is now answered by it and by nothing after it: a Jira axis reads `token_env` or `JIRA_API_TOKEN`, and with neither set the tracker says "no API token reached this tracker" and names the variable. GitHub projects, and projects that name no vendor, read the pair as before.
