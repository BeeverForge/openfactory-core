**Each read of the API declares the shape it answers in.** The floor, the jobs, a job's detail, the board, attention, the inbox, the budget, the decisions, the loops, the messages, the product room, its documents, the metrics, whoami and the action catalogue each name their fields in the description the API serves, so a front end of one's own no longer has to read the panel to learn them. The bodies are unchanged: a key no field names, a number as it was computed, and a row that lacks a field or carries a null are answered as before. A value of another type than its field declares is no longer passed through: it is converted where the model can (`"3"` becomes `3`, `"yes"` becomes `true`), and a value it cannot convert fails the read.

**Every refusal of an action says why in a word a program can read.** A refused action answers `data.reason` beside its `code`: the code itself where nothing finer applies, and otherwise one of `bad_parameters`, `bad_ref`, `out_of_scope`, `not_admin`, `engine_unreachable`, `raised`, `reported_nothing` or, for a name no action has, `unknown_action` — so a credential scoped away from an area and an actor who is not an admin, both `denied`, are told apart. `/api/actions` lists each action's possible reasons as `refusals`.
