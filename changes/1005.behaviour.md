**A YAML file a repository holds is read without expanding aliases, and within bounds.** Every YAML document the core reads goes through one loader. The core's own files (the manifest, `product.yaml`, the published system map, card, capability and document front matter, flows, the knowledge bundle, the registry, a rubric, a battery, thresholds and profiles) are read with anchors and aliases refused, and each reader answers such a file the way it already answers one it cannot read, with a sentence that names the anchor or alias, its line and the remedy, such as "an anchor (`&base`, line 4): this file is read without anchors or aliases — write the value out where it is used". Compose files, CI pipelines, Kubernetes manifests, OpenAPI documents and decision records, whose formats have anchors, still read them, with each alias counted at the size and depth of the value it repeats. Every document is read to 1,000,000 bytes, 100 levels of nesting, 200,000 values and 10,000,000 bytes of values with its aliases counted, and one past a bound is refused by name before anything is built from it: a `product.yaml` nested a thousand levels deep no longer raises out of its readers, and an aliased front matter is no longer written out in full when its title is read. A published system map that cannot be read is now named among the product role's blind spots for the turn, with the file and the reason, where it was treated as absent. What the core writes never carries an alias.
