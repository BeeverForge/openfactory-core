**A running deployment says whether it is alive, whether it can work, and which version it runs, and its logs can be JSON lines.** `/healthz` answers 200 while a process serves, and `/readyz` answers 200 when the durable engine answers, the registry reads and the identity provider can admit, or 503 naming each check that failed; neither needs a credential, the panel answers both on its own port and the worker on `OPENFACTORY_HEALTH_PORT`. The compose file uses `/readyz` as the worker's and the panel's healthcheck, so a process that cannot reach the engine is reported unhealthy instead of running. `GET /api/v1/version` answers the package version, the image the process runs from, the kind of address the engine is reached at, and every installed add-on with its distribution, version, axis and kind. With `OPENFACTORY_LOG_FORMAT=json` the worker and the panel write one JSON object per line, with `ts`, `level`, `logger` and `message`, plus `project` and `product` when the record concerns one and `deployment` when `OPENFACTORY_DEPLOYMENT` names it; the default format is unchanged. The compose healthchecks ask every 15 seconds, so the panel's log gains one `uvicorn.access` line per probe in either format, and the worker's says once where it answers and once when a check starts failing.
