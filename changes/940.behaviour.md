**Four more reads of the API are typed and served under `/api/v1/`, and the rest are named.** `GET /api/v1/projects`, `GET /api/v1/address`, `GET /api/v1/coordinator/messages` and `GET /api/v1/promote/{project}/{issue}` declare the model they answer in, and their old addresses — `/api/projects`, `/api/address`, `/api/coordinator/messages` and `/api/promote/{project}/{issue}` — answer the same body as aliases marked deprecated in the API's description, through the 0.7 series like the other aliases. Three JSON reads stay outside `/api/v1/` on purpose, and `docs/reference/the-front-end-api.md` names each with its reason: `/api/factory/{project}` (the default panel's operator cockpit), `/api/jobs/{project}/{issue}/events` (a run's raw journal rows) and `/api/preview/{project}/{unit}` (still being designed). A read added under `/api/` that is neither typed nor named there now fails the tests. The default panel keeps working unchanged.
