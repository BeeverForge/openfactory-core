**A stored credential can come from a mounted file, and the box image can be pulled with a credential of its own.** Every secret the factory reads now comes through one credential store, named by a reference: a variable name as before, `env:<NAME>`, `file:<name>` for a file in `OPENFACTORY_CREDENTIAL_DIR`, or `<kind>:<name>` for a store an installed add-on declares (`credential_store.<kind>`).
- Set `OPENFACTORY_CREDENTIAL_STORE=file` and `OPENFACTORY_CREDENTIAL_DIR=/run/secrets` to read the factory's own credentials (the harness tokens, the GitHub App key, the bot and per-axis tokens, the panel's tokens, the engine's key) from files named like their variables; a variable still answers where no file does, so secrets can move one at a time.
- A project's `token_env` may name a reference, such as `token_env: file:acme-jira`.
- A file is read at each use and refused, by name and with no fallback to the variable, when anyone but its owner can write to it or its directory, when it leads out of the directory, when it is not a regular file, or when it is larger than 64 KB.
- `box.pull_credential` (a reference) and `box.pull_username` give a project's box image its registry login: it is used for that one pull, from a client configuration deleted afterwards, and never reaches the box or the worker's shared docker configuration.
- `openfactory doctor` has a `credential_store` line naming where credentials come from and every reference the project names, by reference and store, never by value.
