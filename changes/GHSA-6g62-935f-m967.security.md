**An agent role reaches only the tools it is given.** Every harness started every role — the product role that answers people, the executor, the tech lead and the reviewer — with the MCP servers of the account running it beside the role's own tools: that account's hosted connectors, its plugins' servers and its own MCP configuration. Now every command the platform hands a harness starts it with none. Claude Code, the native reviewer included, carries an empty, strict MCP configuration. Codex leaves the account's `config.toml` unread and still reads the login. OpenCode is handed a configuration directory made for the run, empty and removed when it ends, with `OPENCODE_CONFIG` and `OPENCODE_CONFIG_DIR` emptied. Kimi Code, which cannot be started without the account's servers, is not started while `~/.kimi-code/mcp.json` or an installed plugin declares one, and neither is OpenCode while `~/.opencode/opencode.json` exists; the person reads which file held the role back and what to do. Details in GHSA-6g62-935f-m967.
