**A machine's git configuration can no longer widen which transports the core's remote git calls use.** A host whose git configuration allowed `protocol.ext` let a remote named `ext::…` run a command on the host when the core cloned, fetched, listed or pushed it. Every clone, fetch, ls-remote, push and `remote set-url` the core runs on the host now pins its transports: https and ssh are allowed, file is allowed for user-initiated calls, and ext, fd, http, git and any other protocol are refused, whatever the machine's configuration says. A `GIT_ALLOW_PROTOCOL` variable in the core's environment still overrides the pin (see docs/operations.md).
