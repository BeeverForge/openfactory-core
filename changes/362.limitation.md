**On Kimi Code, the planner and read-only questions are read-only by instruction only.** `kimi-code` 0.31.1 refuses plan mode beside a prompt and has no sandbox-policy flag, so nothing but the instruction keeps those roles from writing. The planner runs on the job's own workspace, so a file it writes is committed into the pull request with the executor's work, and with `--sandbox worktree` that workspace is a directory on the host. The read-only questions (the sizer, the tech-lead, the product role, card drafting and judging, documents) run on the host whatever the sandbox setting, in a directory nothing commits from, and nothing confines a write to it. A per-run agent file with a `tools:` list would enforce it and is not used yet. Give the planner and the judging roles another harness where that matters.
