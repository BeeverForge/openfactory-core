**On Kimi Code, the planner and read-only questions are read-only by instruction only.** `kimi-code` 0.31.1 refuses plan mode beside a prompt and has no sandbox-policy flag, so nothing but the instruction keeps those roles from writing. The planner runs on the job's own workspace, and a planner pass that writes there holds the job. The read-only questions (the sizer, the tech-lead, the product role, card drafting and judging, documents) run on the host whatever the sandbox setting, in a directory nothing commits from, except `env context --ask`, which asks in the checkout it is pointed at, where a write is left in that working tree, and the independent review, which runs in the job's box on the job's workspace before the push, where its write can reach the pull request; nothing confines a write to any of them. A per-run agent file with a `tools:` list would enforce it and is not used yet. Give the executor (which also plans), the reviewer and the judging roles another harness where that matters.
