**On Kimi Code, a planner that writes to the job's workspace stops the job.** Its read-only role is an instruction only, and a file it wrote was committed into the pull request with the executor's work, or pushed to the job's branch when the planner then hit a rate limit. The job is now held, naming what the planner wrote, before anything is pushed, and the workspace is discarded; a workspace git cannot read holds the job too, in git's own words. This applies only to projects that turned `planner_stage` on.
