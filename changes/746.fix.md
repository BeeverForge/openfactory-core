**A card runs again on the worktree box after git has forgotten its previous working tree, or after an earlier run was killed while git was checking it out.** When the deployment refreshed its copy of a repository, git otherwise lost track of a card's earlier working tree, or the process died in the middle of creating it, the next run of that card stopped, on git's `already exists` or on a lock nobody had made, and parked. The job now removes a leftover it can prove is its own working tree of that repository and starts, and leaves anything else at that path as it is, a lock a person made included, saying whose it is and the command that moves it.
