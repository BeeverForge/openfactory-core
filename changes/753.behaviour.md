**A pull request waiting on a person, for their review or for the click that merges it, can have a column of its own, apart from the cards that are stuck.** The factory now sends it to the lifecycle key `needs_review`, and a board that has a column for that key puts it there instead of in Needs Action; the board reads a card there as waiting on a person. A board with no such column keeps putting these pull requests in Needs Action, as before. Needs Review covers the whole human gate at the pull request, the review and the merge click: the factory has one gate there and does not tell the two waits apart, so a pull request a person approved and has yet to merge stays in Needs Review until it is merged. A board `openfactory project init` creates from now on has seven columns, with Needs Review between In review and Needs Action. To opt in an existing board: on the platform's own board, re-run `openfactory project init`, which adds the missing column in its place and renames nothing (unless another column is already called `Needs Review`: it then adds none and says how to opt in, by naming `needs_review` under `columns`); on GitHub Projects, add a Status option named `Needs Review` by hand (or name yours under `columns`); on Jira, name the status under `status_map`; on Azure Boards, name the column under `columns` and the state under `state_map`. Opting in moves no card: a pull request already in Needs Action waiting on a reviewer stays there until the factory next moves it (a re-review sends it to Needs Review, the merge to Done); on GitHub Projects, Jira or Azure Boards you can also move it to the new column by hand. A column already called `Needs Review` counts as mapped on GitHub Projects and on the platform's own board; on Jira and Azure Boards it is read as the review wait when a person puts a card there, but the factory moves cards into it only when the map names it. The name `Needs Review` is `needs_review`'s only while the map gives it to no other key: a park already called `Needs Review` (`needs_action` mapped to it) is still read as a park, and a review column already called `Needs Review` (`in_review` mapped to it) is still the factory's review, so the factory sends a pull request waiting on a person to Needs Action there, not into it. Two keys mapped to one status (`in_review` and `needs_review` both `In Review`, or both `In review`) read back as `in_review`. Triage's *waiting too long* finding covers a pull request left in Needs Review; the product role's review of parked cards does not list it.
