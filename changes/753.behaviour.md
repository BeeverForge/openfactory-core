**A pull request waiting on a person, for their review or for the click that merges it, can have a column of its own, apart from the cards that are stuck.** The factory now sends it to the lifecycle key `needs_review`, and a board that has a column for that key puts it there instead of in Needs Action; the board reads a card there as waiting on a person, and the factory's own review may have rejected it. A board with no such column keeps putting these pull requests in Needs Action, as before. Needs Review covers the whole human gate at the pull request, the review and the merge click: the factory has one gate there and does not tell the two waits apart, so a pull request a person approved and has yet to merge stays in Needs Review until it is merged. A board `openfactory project init` creates from now on has seven columns, with Needs Review between In review and Needs Action. Triage's *waiting too long* finding covers a pull request left in Needs Review; the product role's review of parked cards does not list it.
