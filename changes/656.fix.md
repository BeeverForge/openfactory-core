**Two processes on one machine no longer change the same repository checkout at the same time.** The repository cache held its lock per process, so on a deployment where the panel and the worker run on the same host, both could sync one project's checkout at once. One process deleted and re-cloned the checkout the other was resetting, git failed with "already exists and is not an empty directory", and a fresh project was filed an impediment card. The lock on each cached checkout is now a file lock that every thread and every process sharing the cache directory respects. A process that dies while holding it releases it, and a sync that cannot have it within thirty minutes gives up and says so, as any failed sync does. The compose deployment was not affected: only its worker uses the cache.
