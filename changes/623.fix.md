**A job that continues a pull request waits for you when its branch is checked out somewhere else.** On a machine running the worktree box, an adjust, a repair or a resumed job failed with git's own sentence when the card's branch was out in another working tree, such as a tree you made to review the pull request, or your own checkout, and `resume` only reopened the gate. The job now holds, names the path that has the branch and the command that frees it, and `resume` checks again. The command keeps what you have there: when the job continues the pull request, commit and `git worktree remove` the tree; when it builds the branch again, `git switch -c` to a branch of your own. A review tree deleted with `rm -rf` still holds the branch, and the card says so. Nothing the job did not create is removed, a tree of the job's own that you locked is left as it is, and the job no longer runs `git worktree prune` in your repository.
