**A product can start before its code.** `openfactory product start <name> <context-repository>` registers a project with its context repository and no code repository (on one machine the context is created when it does not exist); its product owner's conversation, its requirements and its context work at once. Everything that needs code refuses it by name, naming the way through: every action row that needs the code (reason `no_code_yet`), pickup, `box prove`, `run`, `poll` and `project init`, and the doctor says it once, as its `code` line. An acceptance records the promise and says its breakdown waits for the code. `openfactory product first-source <name> <path-or-url>` then adds the code repository to `sources:` in the context and records it in the registry, and the breakdown needs no other step. Both are action rows (`product_start`, `product_first_source`), reachable from `POST /api/act/{name}`; the onboarding guide says where a context comes from — created, reused or brought in.
