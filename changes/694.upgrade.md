**A command line run on the host, with no metrics store declared, now keeps a file `audit.db` beside its `registry.yaml`.** Every action it runs writes its record there (`~/.openfactory/audit.db` by default, or the file `OPENFACTORY_METRICS_DB` names), so a backup or a copy of that directory now carries it, and `openfactory audit` on that host reads it back; a deployment that declares a metrics store, compose included, writes its records there instead, as rows of kind `audit`. Nothing has to be done. On a sqlite store a record past its period is no longer read, but its bytes stay in the file until a purge of expired rows runs, and nothing runs one yet.
