**A command line run on the host, with no metrics store declared, now keeps a file `audit.db` beside its `registry.yaml`.** Every action it runs writes its record there (`~/.openfactory/audit.db` by default, or the file `OPENFACTORY_METRICS_DB` names), so a backup or a copy of that directory now carries it, and `openfactory audit` on that host reads it back; a deployment that declares a metrics store, compose included, writes its records there instead, as rows of kind `audit`. Nothing has to be done. On a sqlite store a record past its period is no longer read, and the worker and `openfactory serve` delete it from the file as they start — every other row kept for a period too, at most 10,000 a store each start.
