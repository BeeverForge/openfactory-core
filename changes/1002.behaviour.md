**A product's system layer is read through the front-end API, and the product page draws it.** `GET /api/v1/product/<project>/system` answers the map the knowledge refresh publishes at `.okf/system/` in the product's context repository: the sources read, the components and the links between them, the HTTP and gRPC interfaces with their operations, the events, the databases and their schemas, the queues, the infrastructure, the decision records, and what could not be derived — every entry with the repository, file, commit and line it came from, and names only, never the value of a variable. `state` says whether the map was read (`published`), is not there yet (`not-published`) or could not be read (`unreadable`), and `why` says it in a sentence; the map's fields are null unless it was read, so a map that is not known is never answered as an empty one, and a source the refresh could not check out is answered as a `source-unreadable` entry. A map with one file that cannot be read is answered as unreadable, never with that file's parts left empty. The product page has a System tab, read when it is opened, that draws the map with what could not be derived first. A project with no product role is answered with the same 404 an unknown project gets; the read pushes nothing and files no impediment.
